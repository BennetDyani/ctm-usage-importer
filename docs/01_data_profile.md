# 01 — Data profile

Every file in the two sample sets was opened and profiled with a script. The numbers below come from the raw CSVs, not from estimates.

## Sample sets received

| Set | Environments | Period | Notes |
|---|---|---|---|
| `Usage_BANK_2026/` | Dev, Prod, UAT | 2025-06-02 → 2026-06-01 (365 days) | Includes BMC-generated `_total` files for **all three environments combined**, so it can serve as ground truth |
| `USAGE Report for DCS/USAGE/{PROD,QA}/` | PROD, QA | 2025-06-19 → 2026-06-18 (365 days) | Each folder's `_total` files cover **that environment only**. The combined figures appear nowhere in the export. |

## File types

| File | Pattern | Upload in Phase 1? | Layout |
|---|---|---|---|
| File 1, distributed tasks | `ALL_per_task_<ENV>.csv` | **Yes (required)** | Line 1: title `Total Tasks By Date (All Control-Ms)`. Line 2: blank. Line 3: header `Date,Total Task Count,File Transfer Tasks,MFT File Count`. Then 1 row per day, newest first. |
| File 2, distributed endpoints | `ALL<ENV>.csv` | **Yes (required)** | Line 1: title `Total Server Endpoints Per Day (All Control-Ms)`. Line 2: blank. Line 3: header `Date,Endpoint Count`. Then **2 rows per day** (see quirk Q1). |
| Add-ons | `addons_<ENV>.csv` | Optional | Header `Product,Installed,Details`. 21 products, `Installed` or `NA`. Details hold the last job execution date. |
| Derived | `addons__total.csv`, `ALL_per_task__total.csv`, `ALL_per_endpoint __total.csv` (note the space), `*_most_active_dates.csv/.pdf` | **No** | Reports generated by BMC's tool. We recalculate these ourselves and use them only to check our numbers. |
| `reports.zip` (DCS only) | — | **No** | Truncated archive with no central directory. Its first entry is `PROD_CTM_UNAUTHORIZED_LOGINS.csv`, which is unrelated to usage. Out of scope. |

Dates use the format `YYYY/MM/DD`. Every value is a non-negative integer.

## Quirks found

| # | Finding | Evidence | Handling |
|---|---|---|---|
| Q1 | **Every date appears twice** in `ALL<ENV>.csv`: the first row holds the value and the second row is always `0`. | All 5 endpoint files, 730 rows each for 365 dates. Second-row non-zero count = 0. | Store **both** rows exactly, numbered by `line_no`. The daily value is the **sum** of rows for that date. Summing is correct even if the second row is ever non-zero, because the file title says "All Control-Ms", meaning the rows are per Control-M server. |
| Q2 | The newest day in each export is a partial day showing 0 (e.g. DCS 2026-06-18 has 0 tasks and 0 endpoints). | DCS PROD and QA each have 1 zero-task day. | Keep it, and show it in the report as "low/zero days". It cannot affect the 4th highest. |
| Q3 | The BANK `_total` files equal Dev + Prod + UAT added per day, on **every** date (0 mismatches for both tasks and endpoints). | Script cross-check | Confirms rule R2 and gives us **known answers** to test against. |
| Q4 | The DCS `_total` files equal the **single environment**, not PROD + QA (364 of 365 dates differ from the combined sum). | Script cross-check | Shows why the tool is needed: the combined figure is nowhere in the export. |
| Q5 | The add-on `Details` column mixes formats: `Last job execution 20260617)` (note the stray `)`) in per-environment files, and `Dev, UAT, Prod` in totals. | addons files | Store as raw text. Do not parse it in Phase 1. |
| Q6 | Environment case differs between sets: `Prod` vs `PROD`. | File names | Compare environment names case-insensitively, and store them as written in the file name. |
| Q7 | BANK has no file-transfer activity (`File Transfer Tasks` and `MFT File Count` are all 0), and its add-ons show Advanced File Transfer and MFT as `NA`. DCS PROD has both installed and in use. | Data and add-on files agree | Good sanity check for the add-on section of the report. |
| Q8 | No mainframe or SCRT sample is provided, so no MIPS data exists. | — | MIPS is modelled but not built. Reported as "No MIPS data loaded". |
